# v4 — 精排（复合分数）与 MMR 多样性选择

> `v4_rerank_mmr.py`，818 行（检索/理解/引擎沿用 v1-v3）。
> 评测：**7/9**——q5 翻正、q8 排序债还清、q4 出现一次「诚实的回归」。

## 核心洞察

**相关性最高的 top-N 经常互相冗余；而且精排必须放在合并之前。**

v3 留下三笔债：候选池里 RRF 分与 BM25 原始分量纲混杂、近重复对挤在一起、
faq-04 压着正确答案 faq-03。v4 在检索与生成之间插入 `CHUNK_RERANK`，一次
cross-encoder 调用把所有候选**统一重打分**，量纲问题瞬间蒸发；然后：

```
模型重打分（量纲统一 [0,1]）
  → 阈值过滤（≥0.2）+ top1 兜底（≥0.15 保一条）
  → 复合分数 = 0.6*模型分 + 0.3*基础分 + 0.1*来源权重，× 位置先验
  → MMR 贪心：每轮选 λ*相关性 − (1−λ)*冗余度 最大者（λ=0.7）
```

链序上，精排在合并（v5）**之前**是刻意的效率设计：先把 15 条候选筛成 5 条，
合并阶段才不用对 10 条陪跑结果做父块还原、邻居扩展这些要回表的贵手术。

## 运行方式

```bash
python v4_rerank_mmr.py --eval --mock
python v4_rerank_mmr.py --query "青鸟通过哪些机制保证消息可靠投递？" --mock
```

## 代码走读

### 1. 复合分数（↔ `rerank.go:439-460`）

```python
composite = 0.6*model_score + 0.3*clamp01(base_score) + 0.1*source_weight
composite *= position_prior          # 1 + clamp(1 - start/(end+1), ±0.05)
```

- **0.6 模型分**：cross-encoder 对「查询-文档对」整体打分，是三项里唯一真正
  理解语义的，权重过半；
- **0.3 基础分**：检索阶段的旧分数作为先验。一个诚实的观察：混合检索场景下
  基础分是 RRF 分（~0.01 量级），乘 0.3 后贡献趋近于 0——**这一项真正起作用
  的是单路退化场景**（如 FAQ 库向量分 ∈ [0,1]）。课程对基础分先 `clamp01`，
  防止扩展带回的 BM25 原始分（>1）炸穿权重；
- **0.1 来源权重**：web_search 来源 0.95、其余 1.0（:440-446）——外部网页
  可信度略降级；
- **位置先验**（:447-450，SPEC 之外的实现细节）：文档开头的块最多 +5%——
  开头通常是定义与总述。上限 ±5% 保证它只是个温和的 tiebreaker。

### 2. MMR：为什么不能直接取分数前 N（↔ `:463-543`）

```python
mmr = λ * relevance - (1-λ) * redundancy   # λ=0.7（:223）
```

贪心选择，冗余度 = 与已选集合的**最大** Jaccard（:501-506）——不是平均：
只要与任何一条已选高度重合就该罚，平均值会稀释惩罚（有单测演示这个差别）。
分词用 `TokenizeSimple`（textutil.go:40-63）：jieba 多字词、单字 token 过滤；
课程无 jieba 依赖，用汉字 bigram 近似，性质一致。

**λ 敏感性实测**（q5 的真实候选池）：

| λ | rel-v2-01 的名次 | 含义 |
|---|---|---|
| 0.7（WeKnora 取值） | 第 3 | 相关性优先，冗余罚是温和的 tiebreaker |
| 0.5 | 第 4 | |
| 0.3 | 第 5（垫底） | 多样性优先，近重复被压到最后 |

### 3. 阈值的三层安全网（↔ `:148-179,379-421`）

1. **阈值过滤**：模型分 ≥ 0.2（默认，`retrieval_config.go:72-78`）才保留；
2. **top1 兜底**（:390-408）：全滤空但最高分 ≥ 0.15 → 保一条。注释原话的
   精神：强扭的瓜总比没有瓜好——但太烂的瓜（<0.15）宁可不要；
3. **降级重试**（:148-179）：还是空且原阈值 > 0.3 → 阈值 ×0.7（下限 0.3）
   重试一次。

**代码考古发现**：第 2 层让第 3 层几乎成为死路径——模型返回非空时 top1
兜底总是先接住，只有模型返回**空列表**（如 API 侧过滤）才走到降级重试。
从 git 视角看，top1 兜底是后加的安全网，叠在更早的降级机制上。两层都保留
是防御性编程；课程如实复刻并用测试钉住这个交互
（`test_degradation_fires_only_on_empty_response`）。

### 4. 全失败路径降级（↔ `:130-144`）

精排 API 炸了 → `state.search_result` 原样保留、`return next()` 继续走，
下游退回检索排序。与 v2 查询理解同一条纪律：增强插件绝不当单点故障。

## 评测记录

`python v4_rerank_mmr.py --eval --mock`：**7/9**（与 v3 持平，但内容大变）。

| 变化 | 题 | 说明 |
|------|----|------|
| MISS → **PASS** | q5 | 从 v0 起一直 MISS 的题终于翻正。mock cross-encoder 给 rel-v2 打分高于 arch 系列（rel-v2 含「重试机制」，命中查询里的「机制」），rel-v2-01 进入 top-3。诚实说明：**这主要是复合分数的功劳**——语料的近重复对是「改写式」而非「复制式」，bigram Jaccard 仅 0.198，λ=0.7 下 MMR 罚不动它们（两条仍同在 top-3）。「复制式」近重复的教科书场景由单测 `test_mmr_suppresses_near_duplicate` 演示，λ 敏感性见上表 |
| 排序债还清 | q8 | faq-03（免费版）终于压过 faq-04（专业版）——模型分看的是「查询-文档对」，免费版查询配免费版文档得分自然更高。v2/v3 埋的伏笔在此兑现 |
| 名次提升 | q7 | bp-01 从 v3 的第 3 升到第 1 |
| PASS → **MISS（回归）** | q4 | sdk-03 模型分 0.158 < 阈值 0.2 被滤掉。这是**诚实的回归**：v0 文档早就把 q4 的 PASS 标注为「侥幸双命中」——sdk-03 只回答了问题的一半（qos 含义），整体相关度确实不高。真正的修复是 v5 短块邻居扩展，而且它**不依赖 sdk-03 被检索到**（通过 next_chunk_id 链接找邻居） |
| 仍 MISS，变薄了 | q3 | deploy-02（0.111）/deploy-03（0.056）模型分过低被滤，top-3 只剩 deploy-01。同 q4：部署步骤的中后段单看与查询相关度低。v5 重叠拼接来救 |

**贯穿版本的教学信号**：每一层优化都可能打破上一层的侥幸。q4/q3 的回归不是
bug，是精排「按整体相关性无情打分」的正常行为——它暴露出这两题真正需要的
不是更好的排序，而是**把碎片拼回完整上下文**（v5 的主题）。

## 这个版本证明了什么 / 牺牲了什么

**证明了**：
- 统一重打分一举抹平 v3 遗留的量纲混杂（RRF 0.01 vs BM25 4.2 → 全部 [0,1]）；
- 复合分数修好了纯检索分修不好的排序（q5/q7/q8 三题的名次变化）；
- 阈值+兜底+降级的三层安全网，以及「增强不当单点故障」的降级纪律。

**牺牲了（谁来补）**：
- q4/q3 需要的是内容完整性而不是排序——父块还原、重叠拼接、短块邻居扩展
  → **v5 合并四术**
- FAQ 结果仍以原始 Q/A 文本混在候选里 → v5 FAQ 格式化
- 历史只参与了改写，没有作为上下文片段进入 prompt → v5 历史相关片段
- LoggingBoost 还挂在 CHUNK_SEARCH 上；真正的 WikiBoost 装饰器（×1.3 重排）
  应该挂在 CHUNK_RERANK 上、在精排之后叠加 → v6
