# 流量控制与背压

## 背压：当下游追不上上游

当某个主题的未消费积压超过高水位线（默认为分区容量的 80%）时，接入网关会对该主题的所有生产者实施背压：此时 publish 调用不会抛出任何异常，而是被静默挂起，直到积压回落到低水位线以下才放行。从应用侧看，直观表现是调用线程长时间阻塞、发送吞吐骤然下降为零，而客户端与服务端日志中都没有错误记录。排查时应优先查看监控指标 backpressure_active 与消费端的消费速率，而不是在错误日志里寻找线索；解决办法是扩容消费者或临时提高分区容量，而不是重启生产者。

## 令牌桶限流

背压之外，接入网关还对每个 API 密钥维护一个令牌桶限流器，桶容量与补充速率由套餐决定。与背压不同，超出速率的请求会立刻收到限流错误而不是被挂起，客户端应按指数退避重试。限流保护的是网关自身的公平性，背压保护的是下游消费链路，两者解决的是不同层面的问题。
