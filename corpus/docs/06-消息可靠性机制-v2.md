# 消息可靠性机制说明（v2，2025-06 修订）

青鸟的投递保证是「至少一次」，由发送、存储、消费三个环节共同实现。发送侧：SDK 内置指数退避重试机制，publish 失败后默认重试 3 次，起始间隔 200 毫秒、逐次加倍。存储侧：broker 将消息写入预写日志并刷盘之后才应答生产者，确保已确认的消息在断电场景下依然安全。消费侧：客户端处理完成并回传 ACK 后消息才算投递完成，可见性超时内未确认会触发重投。本次修订新增：自 2.3 版本起支持幂等生产者，SDK 为每条消息附带 producer_id 与单调递增序列号，broker 端据此去重，配合 qos=2 可将端到端语义提升为「精确一次」，无需业务方自行实现幂等。
